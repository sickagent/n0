# n0: безопасный мост между AI-агентом и вашими данными

Ваш AI-агент умеет писать SQL. Но стоит ли давать ему пароль от production-базы?

`n0` — open-source платформа на Go, которая решает эту проблему. Агент задаёт вопрос, а n0 сам:

- проверяет права доступа;
- ограничивает запросы только безопасными `SELECT`;
- не раскрывает connection string;
- запускает запрос как отдельную задачу;
- возвращает готовый структурированный результат.

Проще говоря: агент получает пользу от данных, но не получает прямой доступ к базе.

## Для чего это может пригодиться

`n0` подойдёт, если вы строите:

- AI data analyst для команды;
- внутреннего корпоративного ассистента;
- embedded analytics в своём продукте;
- self-hosted платформу для доступа агентов к нескольким базам.

Поддерживаются PostgreSQL, MySQL, ClickHouse, SQLite, MSSQL и BigQuery. Есть Web Admin, schema discovery, асинхронные jobs, tenant isolation, шифрование credentials, аудит и plugin registry.

## Как это работает

```text
AI-агент → n0 → проверка запроса → база данных → структурированный результат
```

Агенту не нужно знать, где находится база, какой у неё пароль и как самостоятельно обрабатывать retries, timeouts и хранение результатов.

Проект ещё развивается, но основной сценарий уже работает: подключить источник, изучить схему, отправить запрос и получить результат.
